# continuo 機能紹介動画の制作設計（要約版）

**この文書は要約である。**詳細は [production_design.md](production_design.md) にあり、食い違ったらそちらが正である。

## 1. 何を、どんな順で使うか

**言いたいこと。**キャラクターの絵は AI が書いたプロンプトで、Codex か Nano Banana が描く。それ以外（画面・字幕・組み立て・書き出し・点検）は Claude Code が Remotion で行う。

| 順 | 誰が | 何をする |
| --- | --- | --- |
| 1 | Claude Code | コンテから、1本ごとの台本データと、要る絵の一覧と、絵の依頼書（プロンプト）を作る |
| 2 | Codex か人間 | Codex の枠が足りれば Codex が描く。足りなければ人間が依頼書を Nano Banana へ貼り、画像を `assets/inbox/` へ保存する |
| 3 | Claude Code | 受け取った絵に名前を付け、ffmpeg で緑を抜き、設定画とずれた絵を描き直しに回す |
| 4 | Claude Code | カンバン・カード・pane・コメント欄などを React + SVG で書き、Remotion で組み立てる |
| 5 | Claude Code と subagent | 1秒ごとの静止画をコンテと見比べ、最大3周直す |
| 6 | Claude Code | 1080×1080・30fps・H.264 の MP4 を書き出し、仕様を検査する |

## 2. Codex と Nano Banana の分け方

**言いたいこと。**1本ごとに、着手の前に Codex の残りの枠を見て、どちらで描くかを AI が決める。同じ回の中では混ぜない。

- 要る枚数の1.5倍を描ける見込みがあれば Codex、無ければ Nano Banana
- 途中で Codex の枠に当たったら、その回のキャラクターの絵は全部 Nano Banana で描き直す。絵柄が揃わないとコマ送りの途中で顔が変わるため

## 3. 人間がすること

| いつ | すること |
| --- | --- |
| 最初に1回 | Gemini アプリの設定で「Media watermark」を Off にする |
| 設定画の3案が出たあと | どの絵柄にするかを選ぶ |
| Codex の枠が足りない回ごと | 依頼書のプロンプトを上から貼り、出た画像を順に保存して「保存した」と伝える。ファイル名は変えなくてよい |
| 最初の1本の MP4 が出たあと | 直してほしいことを伝える |
| 10本が揃ったあと | 投稿してよいかを決め、投稿する |

## 4. 費用

**言いたいこと。**追加の支払いは無い。Remotion は個人なら無料で使え、ライセンスの文面にアカウントの作成は書かれていない。ffmpeg は Homebrew で入れた。
