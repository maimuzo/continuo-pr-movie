# continuo 機能紹介動画の制作設計（詳細版）

**この文書が正である。**人間のレビュー用の要約は [production_design_slim.md](production_design_slim.md) にあり、食い違ったらこちらに従う。
何を映すかは [docs/spec/storyboard.md](../spec/storyboard.md)、進み具合は [docs/plans/impl/tasks.md](impl/tasks.md) にある。
調べた値（無料枠・価格・仕様）は **2026-10-28 時点**のもので、各工程の前に確かめ直す。

## 1. 全体の流れ

**言いたいこと。**キャラクターの絵は、AI が書いたプロンプトで作る。まず Codex で作り、Codex の利用枠が足りないときは人間が Nano Banana へ投げて保存する。
画面・字幕・組み立て・書き出し・自己点検は Claude Code が Remotion で行う。

```
コンテ（docs/spec/storyboard.md）
  └→ [Claude Code] 1本ごとの台本データ（src/videos/NN_*.script.ts）と、要る絵の一覧（assets/manifest.json）
       ├→ [Claude Code] 絵の依頼書（assets/prompts/NN_*.md）。プロンプトを1枚ずつ書く
       │     ├→ Codex の枠が足りる → [Codex 画像生成] が描く
       │     └→ 足りない → [人間] 依頼書のプロンプトを Nano Banana へ貼り、画像を assets/inbox/ へ保存する
       │           └→ [Claude Code] 受け取り・緑抜き・設定画との見比べ。ずれた絵は描き直しの依頼書に回す
       ├→ [Claude Code] デフォルメ画面の部品（カンバン・カード・pane・コメント欄・燃料計）を React + SVG で書く
       └→ [Claude Code] Remotion で組み立てる
             └→ 1秒ごとの静止画をコンテと見比べて直す → MP4 を書き出す → ffprobe で検査 → 人間へ見せる
```

| 誰が | 何をするか | なぜその担当か |
| --- | --- | --- |
| 人間 | 絵柄の選択・Nano Banana への投げ込みと保存・最初の1本の確認・投稿 | 無料の Nano Banana はブラウザでしか使えず、方向性の決定と X への公開は人間にしかできない |
| Claude Code | 進行役。台本・プロンプト・画面部品・組み立て・書き出し・自己点検 | 四角と文字でできた画面とコードは Claude Code が得意で、Remotion の Agent Skills がある |
| Codex | 利用枠に余裕があるときだけ、キャラクターの絵を描く | 端末から呼べて人間の手が要らない。ただし利用枠をほかの作業でほぼ使い切っている（2026-10-28 に人間が確認） |
| Nano Banana（Gemini アプリ） | Codex の枠が足りないときの絵 | 無料で使えるのはブラウザの Gemini アプリだけで、人間が操作する（2節） |

## 2. キャラクターの絵を作る道具

**言いたいこと。**プロンプトは1つの依頼書に書き、Codex でも Nano Banana でも同じものを使う。
**1本の動画の絵は、どちらか片方だけで描く。**2つの道具の絵柄は揃わないため、同じ回の中で混ぜない。

| 道具 | 使える経路 | 人間の手間 |
| --- | --- | --- |
| **Codex の画像生成（先に使う）** | ChatGPT の定額プランの利用枠の中。手元の `codex features list` で `image_generation  stable  true` を確かめた | 無し。参照画像は `--image` で渡せる |
| **Nano Banana（Gemini アプリ）** | ブラウザの Gemini アプリの無料枠 | プロンプトを貼り、出た画像を保存する（3節） |
| Nano Banana（Gemini API / Gemini CLI） | **無料枠では画像を作れない。**画像のモデルは有料枠だけ | — |

**どちらで描くかを、1本ごとに着手の前に決める。**
1. その回の絵の一覧（`assets/manifest.json`）から、要る枚数を数える
2. `maimuzo-dev-core:detect-chatgpt-usage-from-webapi` スキルで Codex の残りの枠を見る
3. 要る枚数の1.5倍（描き直しのぶん）を描ける見込みがあれば Codex、無ければ Nano Banana にする

**途中で Codex の枠に当たったとき。**その回の残りは Nano Banana に回し、**その回で Codex が描いたキャラクターの絵も Nano Banana で描き直す。**同じ回の中で絵柄が揃わないと、コマ送りの途中で顔が変わるためである。
この描き直しを減らすため、Codex で描く回は要る枚数を上の手順3で多めに見積もる。

**画像を作ると、Codex の利用枠を文章だけのやりとりより速く使う**（第三者の記事で3〜5倍。[Codex Pricing](https://developers.openai.com/codex/pricing)）。

**Codex の呼び方（2026-10-28 に1枚描かせて確かめた）。**`codex exec` に「組み込みの画像生成で1枚描き、リポジトリの指定のパスへ保存せよ」と書いて渡す。
画像はまず `~/.codex/generated_images/<セッション>/exec-<id>.png` に書かれ、Codex 自身がそれを指定のパスへ写す。1枚で約2.9万トークン使い、5時間枠と週の枠の使用率はどちらも 0% のまま動かなかった。出た画像は 1145×1374 の PNG だった。

```sh
printf '%s\n' "Use your built-in image generation tool to create ONE image, then save the PNG to assets/raw/robot/catch_jump.png. Do not write any other files. Image prompt: ..." \
  | codex exec -s workspace-write -C "$PWD" --image assets/ref/robot.png -
```

**参照画像を渡すときは、プロンプトを標準入力から渡す。**`--image` は後ろに続く引数をすべて画像のパスとして読むので、`--image <画像> "<プロンプト>"` と書くとプロンプトまで画像扱いになり、`No prompt provided via stdin.` で止まる（2026-10-28 に3回とも止まった）。末尾の `-` が「プロンプトは標準入力から読む」の指定である。

## 3. 人間が Nano Banana で描くときの手順

**言いたいこと。**人間がすることは「依頼書のプロンプトを上から順に貼り、出た画像を順に保存する」だけにする。ファイル名は変えなくてよい。
受け取り・名前付け・緑抜き・良し悪しの判定は AI が行う。

| 順 | 誰が | 何をする |
| --- | --- | --- |
| 1 | Claude Code | 依頼書 `assets/prompts/<回>.md` を書き、チャットで「この依頼書をお願いします」と渡す |
| 2 | 人間 | Gemini アプリで新しいチャットを開き、依頼書の冒頭にある設定画（`assets/ref/robot.png` など、その回に出るキャラクターのもの）を添付する |
| 3 | 人間 | 依頼書のプロンプトを上から順に1つずつ貼り、出た画像を1枚ずつ `assets/inbox/` へ保存する |
| 4 | 人間 | チャットで「保存した」と伝える |
| 5 | Claude Code | `scripts/ingest.py` で、保存された順と依頼書の順を突き合わせて名前を付け、緑を抜く |
| 6 | Claude Code | 1枚ずつ見て、プロンプトと違う絵・設定画とずれた絵を描き直しの依頼書にまとめる |

**なぜ同じチャットで続けて描かせるか。**最初に添付した設定画が会話に残るので、2枚目以降は添付し直さなくてよい。

**なぜ保存の順で突き合わせるか。**人間にファイル名を付け直させないためである。`scripts/ingest.py` は保存された時刻の順に並べる。枚数が依頼書と合わなければ、名前を付けずに止まって人間に聞く。

**最初に1回だけ人間がすること。**Gemini アプリの設定で「Media watermark」を Off にする。見える透かし（右下のきらきら）が入らなくなる。見えない透かし（SynthID）は残るが、動画には映らない。

**1日に描ける枚数。**無料の Gemini アプリの上限は公表されていない（2026-10 時点の第三者の記事では、最後に出ていた数字が1日20枚）。1つの依頼書は10枚以内にし、上限に当たったら翌日に続ける。

## 4. 絵の依頼書と、要る絵の一覧

**言いたいこと。**依頼書は Codex にも人間にも同じものを渡す。プロンプトは英語で書く。
**なぜ英語か。**画像生成は英語のプロンプトのほうが指示の取りこぼしが少ないためである。人間が読めるよう、各プロンプトの上に日本語の1行を添える。

依頼書の形（`assets/prompts/01_ready.md`。Claude Code が書く）。

````markdown
# 絵の依頼書 01_ready（2026-11-02）

最初に `assets/ref/robot.png` を添付してください。上から順に貼り、出た画像を順に `assets/inbox/` へ保存してください。

## 1. robot/nap_sofa　ロボットがソファで寝ている
```
Use the attached character sheet. Draw only the robot, sleeping on a sofa, side view.
Solid #00FF00 background. Do not use green anywhere in the character. Bold outlines. Original character.
```
````

要る絵の一覧（`assets/manifest.json`）。Claude Code が台本を書くときに足し、受け取るたびに `status` を書き換える。

```json
{
  "refs": { "robot": "assets/ref/robot.png", "developer": "assets/ref/developer.png" },
  "items": [
    { "id": "robot/nap_sofa", "video": "01", "tool": "nano_banana", "status": "requested" },
    { "id": "robot/catch_jump", "video": "01", "tool": "nano_banana", "status": "ok" }
  ]
}
```

`status` は `todo`（未依頼）・`requested`（依頼書に載せた）・`ok`（使える）・`redo`（描き直し）のどれかである。`tool` は `codex` か `nano_banana` で、2節で1本ごとに決めた値を入れる。

**プロンプトに毎回入れる語。**「背景は #00FF00 の緑一色」「緑を絵の中に使わない」「太い輪郭線」「オリジナルのキャラクター」。
既存のキャラクター名・ロゴ名はプロンプトに書かない（制作方針の issue の「守ること」）。

## 5. キャラクターの作り方

**言いたいこと。**動画を作り始める前に、キャラクターの設定と設定画を固める。以後はそれを毎回参照に渡して描かせる。
設定（見た目・色・性格・プロンプトの核）は [docs/spec/characters.md](../spec/characters.md) が正である。
背景は緑一色で描かせ、手元で抜く。白背景はロボットの白い部分まで抜けるので使わない。

**なぜ先に固めるか。**回ごとにキャラクターを決めると、10本の間で顔や色がぶれる。設定を1か所に置き、プロンプトをそこから作れば、どの回の絵も同じ設定から出る。

| 順 | 誰が | 何をする | できるもの |
| --- | --- | --- | --- |
| 1 | Codex か人間（2節で決める） | 絵柄の違う設定画を3案描く（正面・横・後ろ、ロボット・人間・現場監督） | `assets/raw/style_candidates/*.png` |
| 2 | 人間 | 案から1つ選ぶ | 選んだ1枚を `assets/ref/<役>.png` に置く |
| 3 | Codex か人間 | 設定画を参照に、各回で要るポーズ違いを描く | `assets/raw/<役>/<ポーズ>.png` |
| 4 | Claude Code | 緑を抜き、余白を切り、大きさをそろえる | `public/characters/<役>/<ポーズ>.png` |
| 5 | Claude Code | 設定画と並べて見比べ、色と形がずれたものを `redo` にする | 描き直しの依頼書 |

**設定画は、2つの道具のどちらで描いても後の回で使える。**どちらの道具にも同じ設定画を参照として渡すためである。

**緑の抜き方。**ffmpeg の `colorkey` を使う。ふちに緑が残ったら Python（Pillow）で緑みを消す。

```sh
ffmpeg -i assets/raw/robot/catch_jump.png -vf "colorkey=0x00FF00:0.30:0.08" public/characters/robot/catch_jump.png
```

## 6. キャラクターの動かし方

**言いたいこと。**普段の動きはポーズ違いのコマ送りにする。回り続ける物（歯車・時計の針）だけはパーツに分けて回す。
動画生成 AI で動きを作る方法は、最初の1本では使わない。

| 動かし方 | 使う場面 | なぜ |
| --- | --- | --- |
| **ポーズ違いのコマ送り（主に使う）** | キャラクターの動き全般 | 関節の調整が要らず、陰影のある絵でもそのまま使える。カクカクした動きがコミカルさになる |
| パーツに分けて回す | 歯車・時計の針・メーター | なめらかに回り続ける物は、コマ送りでは表せない |
| 画面側の動き | 移動・拡大・揺れ・集中線・汗 | Remotion の `spring` と `interpolate` で付けられる |
| 動画生成の切り抜き（Flow の Veo） | 使わない。最初の1本より後で見せ場が弱いときだけ検討する | 無料枠は1日5本ほどで、人間のブラウザ操作になる。当たり外れがある |

**コマ送りの速さ。**1秒に6〜8枚で切り替え、切り替えのたびに少し伸び縮みさせる（制作方針の issue の3-2）。
Remotion では `<Sequence>` でポーズを切り替え、`scale` を数フレームだけ 1.08 → 1.0 に戻す。

**ポーズの枚数を絞る。**絵を描く手間がいちばん重いので、1本あたりキャラクターの絵は8枚程度を目安にし、動きの大半は画面側の動きで付ける。

**1枚の全身絵を切り分ける方法は採らない。**腕の後ろに隠れていた胴が描かれていないので、腕を動かすと穴が開く。

## 7. デフォルメ画面の部品

**言いたいこと。**画面は Claude Code が React + SVG で書き、10本で使い回す。
本物の画面は録らない。録らなければ、本番のカンバンへの書き込みも、アカウント名や個人のパスの映り込みも起きない。

| 部品 | 使う回 | 中身 |
| --- | --- | --- |
| `Kanban` | 置くだけの回・カンバン1枚の回・詰まったらひとことの回・チームで入札の回・Direct Chat の回 | 列（`Ready` / `In Progress` / `In Review` / `Blocked` / `Done` / `Direct Chat`）とカード。カードの移動を `spring` で動かす |
| `IssueCard` | 置くだけの回・カンバン1枚の回・詰まったらひとことの回・チームで入札の回・Direct Chat の回 | 題・リポジトリ名（架空）・色 |
| `Pane` | 見える工房の回・止めても続きからの回 | ガラス張りの工房として描く端末。中に吹き出し |
| `CommentThread` | 詰まったらひとことの回・他人のコメントの回 | コメント欄。立場の札（`OWNER` / `MEMBER`）付き |
| `FuelGauge` | 寝て待つ回・チームで入札の回 | 頭の上に浮かぶ残り枠の燃料計 |
| `Meter` | 定額のままの回 | レジのメーター |
| `Caption` / `TitleCard` / `EndCard` | 全回 | 焼き込み字幕・タイトル・締め |
| `Effects` | 全回 | 集中線・汗・煙・びっくりマーク |

**配色と書体は1か所で決める。**`src/theme.ts` に色と書体を置き、全部品がそこを読む。
書体は Google Fonts の和文の太字（候補は M PLUS Rounded 1c・Dela Gothic One。どちらも SIL Open Font License）を `@remotion/google-fonts` で読む。商用でも無料で使える。

**架空の名前だけを書く。**リポジトリ名は `octocat/hello-world` のような実在しないもの、人の名前は出さない。

## 8. Remotion の構成

**言いたいこと。**このリポジトリの根に Remotion の雛形を置き、10本を1つのプロジェクトの10個の `Composition` として持つ。
台本はデータとして書き、組み立てのコードと分ける。

```
continuo-pr-movie/
├── docs/                       # この文書・コンテ・タスク
├── assets/
│   ├── ref/<役>.png            # 人間が選んだ設定画（1人1枚）
│   ├── prompts/                # 絵の依頼書（4節）
│   ├── inbox/                  # 人間が Nano Banana の画像を保存する場所（git に入れない）
│   ├── raw/                    # 名前を付けた描いたままの絵（緑背景）
│   └── manifest.json           # 要る絵の一覧
├── public/characters/          # 緑を抜いた透明 PNG（Remotion が読む）
├── scripts/                    # 受け取り・緑抜き・静止画の一覧作り・仕様検査
├── src/
│   ├── Root.tsx                # 10本の Composition を並べる
│   ├── theme.ts                # 色・書体・尺の決まり
│   ├── components/             # 7節の部品
│   └── videos/01_ready.tsx … 10_direct_chat.tsx
└── out/                        # 書き出し（git に入れない）
```

**1本の台本の形。**秒で書き、フレームへの換算は部品側で行う。コンテの表の1行が、`beats` の1要素になる。

```ts
// src/videos/01_ready.script.ts
export const script = {
  id: "01_ready",
  title: "置くだけで、始まる",
  end: "置くだけ",
  beats: [
    { from: 2, to: 5, action: "human_throws_card", caption: null },
    { from: 5, to: 8, action: "robot_jumps_and_catches", caption: null },
    { from: 8, to: 11, action: "card_moves_to_in_progress", caption: null },
    { from: 11, to: 13, action: "human_drinks_coffee", caption: null },
  ],
} as const;
```

**なぜ1プロジェクトに10本か。**部品と配色を共有でき、最初の1本で直した癖が残り9本に自動で効く。`npx remotion render <id>` で1本ずつ書き出せる。

**入れ方。**`npx create-video@latest` で空の雛形を作り、`npx skills add remotion-dev/skills` で Agent Skills を入れる（[Remotion の Agent Skills の案内](https://www.remotion.dev/docs/ai/skills)）。雛形の選び方の指定は Phase 0 で確かめる。

## 9. 自己点検

**言いたいこと。**人間へ見せる前に、AI が2段で見る。作った Claude Code が見たあと、作業の文脈を持たない Claude Code の subagent にも見させる。
**見るのは静止画である。**動画を AI に直接見せることはできないため、1秒ごとに静止画を書き出して並べる。

| 順 | 誰が | 何を見るか | 合格の線 |
| --- | --- | --- | --- |
| 1 | `scripts/check_spec.sh` | ffprobe で尺・解像度・コーデック | 尺が14.5〜15.5秒、1080×1080、H.264、30fps |
| 2 | Claude Code | 1秒ごとの静止画15枚を、コンテの表と1行ずつ突き合わせる | コンテの全行が、指定の秒の静止画に映っている |
| 3 | Claude Code | 字幕の読みやすさ | 字幕が画面の外へはみ出さず、背景と重なって読めない箇所が無い |
| 4 | subagent | 同じ静止画とコンテだけを渡し、崩れ・違和感・既存キャラクターへの類似を挙げさせる | 指摘のうち「直さないと見た人が誤解する」ものが0件 |

**なぜ Codex に見させないか。**Codex の利用枠は絵を描くほうへ回す（2節）。文脈を持たない subagent でも、作った本人と違う目で見られる。

**静止画の書き出し。**`npx remotion still <id> --frame=<N>` を1秒ごとに叩き、`scripts/contact_sheet.sh` で1枚の一覧画像にまとめる。

**点検の記録。**`out/review/<id>/review.md` に書く（`out/` は git に入れない）。

```markdown
# 01_ready 自己点検（2026-11-02）
| 秒 | コンテ | 映っているか | 直すこと |
| --- | --- | --- | --- |
| 5〜8 | ロボットが跳ね起き、空中でカードを受け止める | 映っている | 受け止める瞬間の手がカードと重なっていない → 位置を直す |
```

**直す回数の上限は3周。**3周で合格の線に届かなければ、止めて人間へ見せる。同じ箇所を直し続けて枠を使い切らないためである。

## 10. 書き出しと X の仕様

**言いたいこと。**1080×1080 の正方形、30fps、H.264 の MP4 で書き出す。音は、動きの瞬間に鳴らす効果音だけを入れる。

| 項目 | 値 | なぜ |
| --- | --- | --- |
| 画面比率 | 1:1（1080×1080） | X はスマートフォンで縦に流し見されることが多く、正方形は横長より画面を大きく使える。縦長は PC の画面で小さくなる |
| フレームレート | 30fps | コマ送りは1秒6〜8枚なので、60fps にしても得るものが無い |
| コーデック | 映像は H.264（yuv420p）、音は AAC（48kHz・ステレオ） | X が受け付ける形式で、どの端末でも再生できる |
| 音 | 効果音だけ。無音で見ても意味が通る作りは変えない（下の「効果音」） | タイムラインは無音で自動再生されるので、音が無くても意味が通る作りが先である |

### 効果音

**言いたいこと。**効果音は数式で合成して作り、素材は持ってこない。無料で、権利の確認も人の手も要らないためである。音楽は入れない。

| 項目 | 決まり |
| --- | --- |
| 作り方 | [scripts/make_sfx.py:1-5](../../scripts/make_sfx.py#L1-L5) が `public/sfx/*.wav` を書き出す。`uv run --with numpy python -I scripts/make_sfx.py` で全部を作り直す |
| 音の種類 | typing（カタカタ）・enter（ターン）・whoosh（シュー）・splat（ペタッ）・spout（ピュー）・swish（スッ）・sparkle（キラン）・pop（ポン） |
| 鳴らし方 | 各回の動画の `SFX` の表に、音の名前・鳴らす秒・音量を書き、Remotion の `<Audio>` を `<Sequence>` の中に置く。秒は場面の動きの時刻の定数から取る |
| 確かめ方 | `ffmpeg -i <動画> -af "silencedetect=n=-45dB:d=0.12" -f null -` で、音が鳴り始める秒が `SFX` の表と合うかを見る |

**素材を使わない理由。**無料の効果音素材は、素材ごとに商用利用とクレジット表記の条件を利用規約で確かめる必要があり、人の確認が要る。合成なら AI だけで作り直せる。音の質は素材に劣るが、おまけの音なので足りる。

**音楽を入れない理由。**15秒に合う曲を選ぶ手間と、権利の確認の手間が大きい。X では音を消して見る人が多いので、得るものが少ない。

**X が受け付ける上限（長さ・容量・解像度）は、Phase 0 で X のヘルプを見て確かめる。**15秒・1080p なら上限に届かない見込みだが、まだ確かめていない。

**投稿は人間が行う。**AI は投稿しない。投稿文の下書き（題・1〜2行の説明・ハッシュタグ）は `out/<id>/post.txt` に書いて渡す。

## 11. 道具の一覧と入れ方

**言いたいこと。**入れる道具はすべて無料か、人間の定額プランの中で動く。人間が入れる必要のあるものは無い。

| 道具 | 役割 | 入れ方・費用 |
| --- | --- | --- |
| Remotion | 動画の土台 | `npm` でこのリポジトリに入れる。**個人は無料ライセンスで、ライセンスの文面にアカウントの作成も登録も書かれていない**（[Remotion License](https://cdn.jsdelivr.net/npm/remotion@4.0.529/LICENSE.md)） |
| Remotion Agent Skills | Claude Code に Remotion の書き方を教える | `npx skills add remotion-dev/skills` |

| Gemini アプリ | 枠が足りないときの画像生成（人間が操作） | 無料。人間のブラウザで使う |

## 12. 進め方と、人間が止まる場面

**言いたいこと。**いまの目的は、通しでどんな作業になるかを確かめることである（2026-10-29 に人間が決めた）。コンテとキャラクターを固め、全回の絵コンテを作ってから、まとめて MP4 に書き出す。
人間が止まるのは下の場面だけで、それ以外は AI が [tasks.md](impl/tasks.md) を上から進める。

| 順 | いつ | 人間がすること | しないと |
| --- | --- | --- | --- |
| 1 | コンテとキャラクターを書き直したあと | コンテと、キャラクターの役の分け方・新しいキャラクターの絵を確かめる | 絵コンテを描き始められない |
| 2 | Codex の枠が足りないとき | 依頼書のプロンプトを Nano Banana へ貼り、画像を保存する（3節） | 絵が揃わない |
| 3 | 全回の絵コンテを描き、AI が構成を点検したあと | 絵コンテを見て、直してほしいことを伝える | 直しの要る絵で、動画を組み立ててしまう |
| 4 | 全回の MP4 を書き出したあと | 見て、投稿してよいかを決め、投稿する | 投稿されない |

**絵コンテとは。**1本ごとに、場面ごとの見本の静止画を Codex で描いたものである。コンテの文字だけでは、構図や混み具合が分からないためである。
**AI の構成の点検とは。**絵コンテとコンテを突き合わせ、話の因果が絵で追えるか、同じキャラクターが別の役に見えないか、混みすぎていないかを、作業の文脈を持たない subagent に見させることである。

**依頼書はまとめて渡す。**AI は、人間が描いている間に画面部品や組み立てを先に進める。依頼書は1回に1本ぶん（10枚以内）とし、描き直しのぶんは次の依頼書の頭に載せる。

**AI が人間に聞かずに決めてよいこと。**部品の形・配色の細部・字幕の位置・コマの枚数・効果の付け方・どちらの道具で描くか。コンテの「何が起きるか」が変わらない範囲に限る。
**コンテの中身を変えたくなったら、止めて人間に聞く。**コンテは人間が確定したものだからである。

**長い作業の前に枠を確かめる。**Claude 側は `maimuzo-dev-core:detect-usage-from-webapi`、Codex 側は `maimuzo-dev-core:detect-chatgpt-usage-from-webapi` スキルで残りを見る。

## 13. 守ること

**言いたいこと。**このリポジトリは public である。既存の著作物を描かず、個人の情報を commit しない。

- **既存のキャラクターやロゴを描かない。**Octocat、Claude・Anthropic のロゴやマスコットは使わない。プロンプトにも既存のキャラクター名を書かない
- **生成した絵の扱いを確かめる。**OpenAI と Google の利用規約で、生成物の権利と商用利用の条件を Phase 0 で確かめる
- **commit しないもの。**`out/`・`node_modules/`・`.venv/`・`.env`・`assets/inbox/`・個人の絶対パス（`/Users/<名前>/`）を含むファイル
- **`assets/inbox/` を commit しない理由。**ブラウザが付けたファイル名や、受け取り前の絵が混ざるため。受け取ったものは `assets/raw/` へ移す
- **`assets/raw/` と `assets/prompts/` は commit する。**同じプロンプトでもう一度描かせても同じ絵は出ないので、元の絵とプロンプトを残す
- **本物の画面を録らない。**録るときは制作方針の issue の「実際の画面を録るとき」に従う

## 14. 検討して採らなかったもの

**言いたいこと。**制作方針の issue の5節で退けたものに加え、今回の設計で次を退けた。

| 候補 | 採らない理由 |
| --- | --- |
| Gemini CLI で Nano Banana を呼ぶ | Gemini API の無料枠では画像のモデルを使えない（2026-10 時点の第三者の記事。Google の料金表に無料枠の記載が無い） |
| Codex だけで全部の絵を描く | Codex の利用枠をほかの作業でほぼ使い切っている（2026-10-28 に人間が確認） |
| AI がブラウザで Gemini アプリを操作する | 画像を保存するたびに人間の許可が要り、人間の手間がかえって増える |
| 同じ回の中で Codex と Nano Banana の絵を混ぜる | 絵柄が揃わず、コマ送りの途中で顔が変わる |
| 人間に保存したファイルの名前を付けさせる | 手間が増える。保存の順で AI が名前を付ける（3節） |
| 白背景で描かせて抜く | ロボットや紙の白い部分まで抜ける |
| 自己点検を Codex にさせる | Codex の利用枠は絵を描くほうへ回す |
| 10本を別々の Remotion プロジェクトにする | 部品と配色を共有できず、最初の1本で直したことを9回直すことになる |
| AI が X へ投稿する | 公開は取り消せない操作で、人間の判断に残す |
| 16:9 の横長で書き出す | スマートフォンのタイムラインで小さく映る（10節） |
